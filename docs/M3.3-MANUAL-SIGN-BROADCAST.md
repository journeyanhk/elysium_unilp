## 0. 第一轮 review 的 P0 修复（2026-11-12）

### P0-1 签名请求显式绑定当前钱包账户

- `WalletTx` 增加 `from`；`eth_signTransaction` / `eth_sendTransaction` 参数均显式携带 `from: tx.from`（不再是 `undefined`）；
- 校验分两道（`frontend/src/lib/tx-sign.ts`）：
  - **第一道（纯函数，不接触钱包）**：门禁/解锁记录/熔断/授权已消费 + `from` 存在且合法 + `chainId === 99901` + `to` / `data` / Gas 参数齐全；
  - **第二道（读取钱包只读状态后）**：`from` 必须等于钱包当前账户（大小写不敏感）、钱包当前链必须等于交易链；
- 任一不满足 → **在请求钱包之前抛错**，不会弹出钱包；
- 后端仍保留签名恢复后的二次校验（`SENDER_MISMATCH`），不依赖前端。

测试（`frontend/src/lib/tx-sign.test.ts`，`cd frontend && bun test`，12 条）：

| 用例 | 结果 |
|---|---|
| `from` 缺失 | 拒绝，且钱包调用次数 = 0 |
| `from` 与当前账户不同 | 拒绝，且无任何签名方法调用 |
| `from` 大小写差异 | 正常通过（统一小写比较） |
| 签名恢复地址 ≠ intent 用户 | 后端拒绝（`SENDER_MISMATCH`） |
| 签名请求携带 `from`（非 undefined） | 断言请求参数中的 `from` 等于账户 |

### P0-2 Gas 参数在签名前绑定

- 新增 `lib/tx-gas.js`：
  - `gasLimit = max(ceil(eth_estimateGas × (1 + 25%)), 50000)`（余量与下限固定且文档化）；
  - `maxFeePerGas = 链上 eth_gasPrice`（必须 ≤ 5 gwei）；
  - `maxPriorityFeePerGas = min(maxFeePerGas, 1 gwei)`；
  - Gas 美元**最坏**成本 = `gasLimit × maxFeePerGas × HYPE 价格 ≤ 1 USD`；
  - 缺估算 / 缺价格 / 缺 HYPE 价格 / 超任一上限 → 计划失败（`GAS_ESTIMATE_MISSING` / `GAS_PRICE_MISSING` / `HYPE_PRICE_MISSING` / `GAS_PRICE_OVER` / `GAS_USD_OVER`）。
- `/simulate` 计算并把 Gas 计划落库（`gas_limit` / `max_fee_per_gas_wei` / `max_priority_fee_per_gas_wei` / `gas_plan_version`）并返回给前端；
- 绑定对象新增 `gasLimit` / `maxFeePerGas` / `maxPriorityFeePerGas` / `gasUsd`（进入 `bindingHash`）；
- **签名前**核对（发送前或事后，同一套检查）：
  `gasLimit ≤ 绑定值`、`maxFeePerGas ≤ 绑定值`、`maxPriorityFeePerGas ≤ 绑定值`、`优先费 ≤ maxFeePerGas`、
  `gasLimit × maxFeePerGas × HYPE 价格 ≤ 1 USD`；绑定缺 Gas 字段或取不到 HYPE 价格 → **直接拒绝**（不做事后补偿）；
- 前端签名请求显式携带 `gas` / `maxFeePerGas` / `maxPriorityFeePerGas`（来自预演锁定值），不省略、不改动。

测试（`backend/tests/tx-gas.test.js` 10 条 + `tests/tx-broadcast.test.js` 新增 5 条 + `tests/tx-presign.test.js` 新增 1 条）：

| 用例 | 结果 |
|---|---|
| `gasLimit` 被提高 | 拒绝（`GAS_LIMIT_OVER`） |
| `maxFeePerGas` 被提高（仍低于门禁 5 gwei） | 拒绝（`GAS_PRICE_OVER`，与绑定比对） |
| `maxPriorityFeePerGas` 被提高 | 拒绝（`PRIORITY_FEE_OVER`） |
| 优先费 > `maxFeePerGas` | 拒绝（`PRIORITY_FEE_ABOVE_MAX_FEE`） |
| Gas 预估缺失 / 绑定缺 Gas 字段 | 拒绝（`GAS_ESTIMATE_MISSING` / `GAS_BINDING_MISSING`） |
| Gas 美元成本超 1 USD | 拒绝（`GAS_USD_OVER`） |
| 无法获取 HYPE 价格 | 拒绝（`HYPE_PRICE_MISSING`，fail-closed） |
| 模拟记录缺 Gas 计划 | 签名前核对直接拒绝（禁止用旧记录签名） |

### 首笔模式约定（按 review）

首笔**只使用 `wallet-sign-raw`**（钱包只签名 → 后端核对 → 后端单次广播）；
`wallet-sent` 为先广播后核对、无法撤回，面板已标注「首笔不建议」。

## 0.1 第二轮 review 的 P0 / P1 修复（2026-11-12）

### P0-1 签名前重新读取服务端最新状态（不再依赖页面旧状态）

- 新增 `POST /api/tx/pre-sign-audit`（**服务端**重新读取 + 写审计快照）：
  1. 重新读取门禁状态（`enabled` / `unlockPath` / **熔断** / `stateSource` / `firstTxMode`，来自持久化）；
  2. 重新读取该 intent 的授权状态（`authorized` / `consumed` / 消费时间 / 消费时长上限）；
  3. 重新执行完整签名前核对（权威模拟记录 + 真实 calldata + 绑定逐字段比对）；
  4. 通过时返回**签名载荷**（`signing`：chainId / to / value / calldata / gasLimit / maxFeePerGas / maxPriorityFeePerGas / bindingHash），
     前端必须使用这份载荷，不得使用页面旧状态；
  5. 把整份快照写入审计（`pre-sign-verified` / `pre-sign-rejected`），字段：
     `gate`（含 version/enabled/unlockPath/killSwitchTripped/stateSource/firstTxMode）、`authorization`（含 status/bindingHash/consumedAt/consumeAgeSec）、
     `bindingHash`、`preSign`（ok/reason/changed）、`walletAccount`、`walletChainId`、`intentUser`；
     审计写入失败 → **拒绝签名**（`PRESIGN_AUDIT_FAILED`，fail-closed）。
- 新增 `GET /api/tx/authorization-state/:intentId`（只读，供前端重新读取授权状态）。
- 前端 `doSign()` 现在**每次都**：重新读取钱包账户与链 → `GET /api/tx/gate`（`cache: no-store`）→ `POST /api/tx/pre-sign-audit`
  → `evaluateFreshSignGate()` 判定（纯函数）→ 任一读取失败或判定不通过 → **直接拒绝，不弹钱包**。
- 判定覆盖：门禁关闭 / 无解锁记录 / 熔断已触发 / **熔断状态未知** / 状态不可读 / 无授权 / 未消费 /
  消费时间缺失或超时 / 服务端绑定哈希与本地不一致 / 重新核对未通过；首笔模式强制 `wallet-sign-raw`。

测试（前端 `bun test`，22 条）：页面旧状态未熔断但服务端已熔断 → 拒绝；旧状态已消费但服务端授权失效 → 拒绝；
门禁读取失败（null / 不可读）→ 拒绝；重新核对失败 → 拒绝；钱包账户切换 / 钱包链改变 → 拒绝；
另有静态断言：`doSign()` 内「新鲜状态核对 → 判定 → 钱包签名」顺序正确，且签名载荷来自服务端 `signing`。

### P0-2 Gas 参数严格等于授权绑定 + 禁止交易类型混用

- `checkGasAgainstBinding()` 由「不得超过绑定值」改为**必须严格相等**：
  `GAS_LIMIT_MISMATCH` / `MAX_FEE_MISMATCH` / `PRIORITY_FEE_MISMATCH`（**降低** Gas 参数同样拒绝 ——
  否则交易 A 的授权可被降级后的交易 B 复用）；
- **交易类型分离**：Gas 计划为 EIP-1559，legacy 交易（仅 `gasPrice`）或同时携带 `gasPrice` 的交易
  一律 `TX_TYPE_MISMATCH`（禁止「绑定 EIP-1559、实际降级 legacy」）；
- 保留绝对上限兜底（`GAS_PRICE_OVER` / `PRIORITY_FEE_ABOVE_MAX_FEE` / `GAS_USD_OVER`）与
  `HYPE_PRICE_MISSING` 的 fail-closed 行为。

测试：`tests/tx-gas.test.js`（严格相等降低/提高、legacy、混合、优先费高于 maxFee、绝对上限兜底）+
`tests/tx-broadcast.test.js`（真实签名交易的 legacy 降级、gasLimit 降低、maxFee 降低）。

### P1 首笔模式服务端禁用 wallet-sent

- `preflightBroadcast()` 增加：`gate.firstTxMode === true && mode === 'wallet-sent'` → `MODE_DISABLED_IN_FIRST_TX`
  （**服务端强制**，不只是 UI 隐藏）；
- 前端在首笔模式下禁用该选项并提示「先广播后核对，无法撤回」。

## 2. 禁止事项与执行方式

| 禁止 | 执行方式 |
|---|---|
| 保存私钥 / 助记词 | 产品代码静态扫描：`lib/`、`routes/` 不得出现 `privateKeyToAccount` / `mnemonicToAccount` / `signTransaction(` / `signTypedData(`（`tests/tx-broadcast.test.js`） |
| 自动签名 | 只有前端用户点击才触发；后端不持有任何签名能力 |
| 自动重试 / 自动重发 | 广播函数为单次调用（无循环、无 `retries`、无 `nonce` 处理，静态断言）；RPC 超时按「结果未知」处理 → 熔断 + 人工确认 |
| 自动加速（speed-up）/ 替换交易 | 不存在相应方法；静态断言禁止 `speedUp/replaceTransaction/bumpFee` 等函数与手工 nonce |
| 自动放宽滑点 / 降低 minOut | 门禁参数上限不可由请求覆盖；签名交易若 Gas 价格高于上限 → 拒绝（`GAS_PRICE_OVER`） |
| 批量无人值守 | 广播必须逐笔手动触发；每分钟 1 笔、每日 3 笔上限由门禁强制 |

## 3. 广播前置检查（全部为硬条件，任一不满足即拒绝）

```
GATE_CLOSED                 交易总开关关闭
NO_UNLOCK_RECORD            缺少解锁记录
KILL_SWITCH                 熔断已触发
GATE_STATE_UNAVAILABLE      熔断状态不可读（未知 = 拒绝）
NO_AUTHORIZATION            没有授权记录
AUTHORIZATION_NOT_CONSUMED  授权未一次性消费（禁止跳过第 5 步）
CONSUMPTION_TIME_MISSING / CONSUMPTION_TIME_INVALID
CONSUMPTION_STALE           消费后超过 limits.broadcastConsumeMaxAgeSec（默认 180s）
BINDING_MISSING / BINDING_MISMATCH  绑定哈希缺失或与当前交易不一致
MODE_NOT_ALLOWED            非两种手动方式
RAW_TX_MISSING / TX_HASH_MISSING    缺少签名交易或交易哈希
```

内容核对失败码（发送前或事后）：
`CHAIN_MISMATCH` / `TO_MISMATCH` / `VALUE_MISMATCH` / `CALLDATA_MISMATCH` / `SELECTOR_MISMATCH` / `SENDER_MISMATCH`。

Gas 核对失败码（M3.3 review 第二轮 P0-2，发送前或事后）：
`GAS_BINDING_MISSING` / `GAS_LIMIT_MISSING` / `GAS_PRICE_MISSING` / `PRIORITY_FEE_MISSING` /
`GAS_LIMIT_MISMATCH` / `MAX_FEE_MISMATCH` / `PRIORITY_FEE_MISMATCH` / `TX_TYPE_MISMATCH` /
`GAS_PRICE_OVER` / `PRIORITY_FEE_ABOVE_MAX_FEE` / `GAS_USD_OVER` / `HYPE_PRICE_MISSING`。

首笔模式：`MODE_DISABLED_IN_FIRST_TX`（首笔只允许 wallet-sign-raw）。

回执核对失败码：`RECEIPT_REVERTED`（熔断）、`POST_BROADCAST_MISMATCH`（熔断）、`GAS_USD_OVER`（记录偏差，要求人工复核，不熔断）。

## 4. 失败 → 熔断对照

| 情况 | 是否熔断 | 理由 |
|---|---|---|
| 节点明确拒绝（nonce too low / insufficient funds / already known） | 否 | 交易未进入内存池，可人工复核后重来 |
| 广播请求异常 / 超时（结果未知） | **是** | 交易可能已进内存池；禁止自动重发，必须人工确认 |
| 签名交易与授权绑定不一致（发送前） | **是** | 参数被改动 |
| 回执 `status != success` | **是** | 交易回滚 |
| 链上交易内容与授权绑定不一致（事后） | **是** | 广播内容异常 |
| 同一 intent 第二次广播 | 拒绝（不熔断） | `ALREADY_BROADCAST` |
| 实际 Gas 成本超上限 | 否（记录偏差 + 要求人工复核） | 成本问题，非安全问题 |
